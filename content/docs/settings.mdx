---
title: Settings
description: What each page in the settings panel controls, and which of them write to disk.
---

Open settings from the gear in the canvas toolbar (or the account row at the
bottom left). The panel has three groups, and one rule runs through all of it:
**it reports what the agent CLIs will actually do, and only writes where the CLI
has no other way to know.**

Everything is stored in `settings.json` in the app's config directory —
`~/.config/termsprawl/` on Linux, or the app's user-data folder for a packaged
build.

## Basics

### General

- **Enter behavior while busy** — what Enter does in a chat node while a reply
  is streaming: queue the message, send it, or ask. Shift+Enter always breaks
  the line.
- **Terminal font** — the font family for new terminals. Empty means the
  built-in default.
- **Inherited terminal profile** — the terminal profile termsprawl asks for when
  it launches a shell, exported as `TERMSPRAWL_TERMINAL_PROFILE` so your own
  shell startup can act on it.
- **HTTP proxy** — routes terminal and agent egress through a proxy. The value
  is exported as `HTTP_PROXY`, `HTTPS_PROXY`, `http_proxy` and `https_proxy` in
  every terminal and agent process termsprawl spawns. Blank means direct.
- **Invert mousewheel zoom** — flips the scroll direction on the canvas.
- **Show the welcome guide again** — replays the three-step first-run guide the
  next time the canvas is empty.

### Appearance

The theme: **light**, **dark**, or **system** (follow the OS). The canvas keeps
its monochrome surfaces and lime accent in every theme; lime is a signal, never
decoration.

### Model settings

Model providers for chat nodes: a name, a base URL, and per-provider API keys
stored on this machine only. Keys are never written into project files, and a
`TERMSPRAWL_PROVIDER_KEY_<ID>` environment variable overrides a stored key.

### Browser

- **Home page** — the URL a new browser node or tab opens. Point it at your own
  SearXNG instance for private search.
- **Allow agents to control browser nodes** — off by default. When on, an
  external agent can open and drive browser nodes over a localhost-only CDP
  endpoint.

## Agent capabilities

### Skills

The skills the agent CLIs on this machine will load, read from their own skills
directories (`~/.claude/skills`, `~/.codex/skills`). Each row shows which agent
it belongs to and whether it is enabled.

**Disabling is real, and reversible.** The toggle moves the skill folder into a
sibling `skills-disabled/` directory that the CLI never scans — nothing is
deleted, and enabling moves it straight back. This is the one place the settings
panel writes to an agent's config tree, and it does so by renaming a folder.

### Hooks

Hooks are how agent CLIs tell termsprawl what a session is doing, which is what
drives the RUNNING / NEEDS YOU badges on agent nodes.

- **Managed by termsprawl** — the hooks our installer wrote into the CLI's own
  config. **Repair hooks** re-runs that installer for the agents in scope; it is
  idempotent, so a second press changes nothing.
- **Not managed by termsprawl** — hook entries another tool installed. They are
  listed for transparency and never touched.

### Commands

The slash commands a chat node intercepts before sending a message (`/clear`,
`/model`, `/system`, `/cost`). The parser is the source of truth: if a command
is listed here, the chat node will act on it.

### MCP Servers

The MCP servers your agent CLIs will start, read from their own config files
(`~/.claude.json`, `~/.codex/config.toml`), with the command or URL each one
launches. This page is **read-only on purpose**: the CLI is what launches the
server, so editing it here could put the panel out of sync with what actually
runs. Add or change servers in the CLI's config file.

## Data and statistics

### Usage

Tokens and cost for your chat nodes, totalled from what the workspace already
saves: every assistant reply records its token counts and timestamp, so this
page needs no collection pass of its own and no data leaves the machine.

- The metric strip totals tokens, the busiest day, the longest session, and the
  current and longest streaks.
- **Token activity** is one square per day.
- **Daily trend** switches between the last 7 and last 30 days.
- **Model usage** breaks the totals down per provider and model, with cost from
  the built-in price table (or your own overrides).

Conversations that never reported tokens — an agent node in a terminal, for
instance — do not appear here.
