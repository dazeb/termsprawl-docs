# Settings

The **cog** in the toolbar (top-right) opens Settings as a full-width sheet over
the canvas — there's no dropdown menu behind it, and nothing to save: each
change applies as you make it. Escape, the **×**, or a click on the backdrop
closes the sheet. Everything lands in `settings.json` in the app's config
directory.

The sidebar groups the pages:

- **Basics** — General, Appearance, Model settings, Browser.
- **Agent capabilities** — Skills, Hooks, Commands, MCP Servers, Subagents,
  Plugins, Agent accounts, A2A peers.
- **Data and statistics** — Usage, Cloud & backup, Connections, Updates.

Pages that don't apply to the running edition are hidden rather than shown
empty. In the Server Edition the desktop-only pages (Browser, Agent accounts,
A2A peers, Connections, Updates) aren't there, and the capability pages say why
they can't read anything: a container has no host config tree to discover in.

## General

**Interaction**

| Setting | What it does |
| --- | --- |
| Enter behavior while busy | In chat nodes `Enter` sends; while a session is busy it queues, sends straight away, or prompts. `Shift+Enter` always breaks the line. |
| Terminal font | The font family terminal nodes use. Empty means the built-in default. |
| Inherited terminal profile | The profile name exposed to spawned terminal processes as `TERMSPRAWL_TERMINAL_PROFILE`, so your own shell startup can act on it. |
| HTTP proxy | Inherited by terminal and agent processes as `HTTP_PROXY`, `HTTPS_PROXY`, `http_proxy` and `https_proxy` when set. Blank means direct. |
| Invert mousewheel zoom | Off (default): scroll up zooms in. On: scroll up zooms out. |

**First run** — reset the welcome guide so the three-step welcome (create a
project, spawn a terminal, arrange) replays the next time the canvas is empty.

## Appearance

**Theme** — Light, Dark, or System (follow the OS). The canvas keeps its
monochrome surfaces and lime accent in every theme; lime is a signal, never
decoration.

## Model settings

**Providers** manages your custom model providers; once configured they can be
chosen in chat nodes. **Defaults and keys** holds the default chat model and the
keys it uses — stored on this machine only, never in project files, and
overridable with a `TERMSPRAWL_PROVIDER_KEY_<ID>` environment variable.

## Browser

**Start page** — where an embedded browser node first goes. **Agent control** —
whether agents may drive browser nodes. See [Nodes](/docs/nodes) for the browser
node itself.

## Skills

The skills the agent CLIs on this machine will load, read from their own
directories (`~/.claude/skills`, `~/.codex/skills`). Each row shows which agent
it belongs to and whether it's enabled; **All agents** / per-agent tabs and the
search box narrow a long list.

**Disabling is real, and reversible.** The toggle moves the skill folder into a
sibling `skills-disabled/` directory the CLI never scans. Nothing is deleted,
and enabling moves it straight back. This is the one place Settings writes into
an agent's config tree, and it does it by renaming a folder.

## Hooks

Hooks are how the agent CLIs tell termsprawl what a session is doing, which is
what drives the RUNNING / NEEDS YOU badges on agent nodes.

- **Managed by termsprawl** — the hooks our installer wrote into the CLI's own
  config. **Repair hooks** re-runs that installer for the agents in scope; it's
  idempotent, so a second press changes nothing.
- **Not managed by termsprawl** — entries another tool installed. They're listed
  for transparency and never touched.

## Commands

The slash commands a chat node intercepts before sending a message (`/clear`,
`/model`, `/system`, `/cost`). The parser is the source of truth: the command
parser is what decides, which is why this page is read-only.

## MCP Servers

The MCP servers your agent CLIs will start, read from their own config files
(`~/.claude.json`, `~/.codex/config.toml`), with the command or URL each one
launches and whether it runs over stdio or HTTP.

This page is **read-only on purpose**: the CLI is what launches the server, so
rewriting its config from here could put the panel out of sync with what
actually runs. Add or change servers in the CLI's own config file and press
**Refresh**.

## Subagents

The reusable subagent definitions the CLIs on this machine will load, read from
their own directories (`~/.claude/agents/*.md`, `~/.codex/agents/*.toml`). Each
row shows what the definition declares: how many tools it may use ("All tools"
when the file doesn't restrict them), and its permission or sandbox mode plus
any MCP servers it brings.

Read-only: the model a subagent runs on and the tools it may use belong to the
CLI that owns the file, so the page reports them instead of offering a picker
that wouldn't reach the CLI.

## Plugins

The plugin bundles cached by the agent CLIs — Codex from
`~/.codex/plugins/cache/<marketplace>/<plugin>/<version>`, Claude Code from the
same shape under `~/.claude/plugins` — grouped by marketplace, with the version
and how many skills and agents each bundle ships.

**Installed** means cached; the toggle is the CLI's own `enabled` flag. Turning
one on writes `enabled = true` for that plugin's table in the CLI's config
(`~/.codex/config.toml`), and turning it off writes `false` — one key, nothing
else in that file is touched. A plugin that is cached but never enabled shows as
off, which is what the CLI does with it.

## Agent accounts

The agent registry and the managed logins for the agent CLIs, with the
permission mode each account runs under. **login** opens a terminal for that
CLI's sign-in flow; **delete** forgets the account. See
[Agents](/docs/agents).

## A2A peers

Agent-to-agent endpoints: which peers you trust, and whether your own nodes are
exposed to them. **test** fetches the peer's agent card; a peer whose key has
changed shows as untrusted until you confirm it. See [A2A peers](/docs/a2a).

## Usage

Tokens and cost for your chat nodes, totalled from what the workspace already
saves: every assistant reply records its token counts and a timestamp, so this
page needs no collection pass of its own and nothing leaves the machine.

- The metric strip shows total tokens, the busiest day, the longest session, and
  the current and longest streaks.
- **Token activity** is one square per day.
- **Daily trend** switches between the last 7 and last 30 days.
- **Model usage** breaks the totals down per provider and model, priced with the
  built-in table (or your own overrides).

Conversations that never reported tokens — an agent running in a terminal node,
for instance — don't appear here.

## Cloud & backup

Your account, encrypted workspace backups, and your hosted canvas space. See
[Cloud](/docs/cloud).

## Connections

The Telegram bot and the relay service — how this machine talks to your phone
and to other machines. See [Relay](/docs/relay).

<Callout type="warn" title="Credentials live in Settings">
  Provider keys, peer tokens and account logins are stored by the app and edited
  here. Don't export them into shells or project files.
</Callout>

## Updates

**Release** shows the auto-download preference. Off (default), you get a toast
when a newer GitHub release exists and you choose when to download; on, the
AppImage or `.deb` downloads in the background and the toast then asks you to
restart. An unpackaged (dev) build says the updater is inactive instead of
offering a control that does nothing.

## Agents

On the Linux desktop, **Agents** lists the supported CLIs with their detected
paths and versions. **Install** adds a missing agent; **Check for updates**
offers updates for installations made through setup. **Open** starts the agent
on a local canvas so you can sign in or choose a provider. Existing installations
are preserved and show vendor/package-manager update guidance.

The same page checks system prerequisites and offers guided installation in a
visible terminal. See [Agents](/docs/agents) and [Getting started](/docs/getting-started).
