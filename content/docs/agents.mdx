An **agent node** is a terminal node preset that launches an AI coding agent CLI
once, inside tmux. The agent runs on your machine, in your project, with its
transcript and status shown on the canvas.

## Supported agents

termsprawl ships presets for five CLIs, plus a custom template:

- **Claude Code** — full support: hooks/status, resume, subagents, recurring, branch, context links, usage, permission mode.
- **Codex CLI** — hooks/status (RUNNING / NEEDS YOU), resume, subagents, permission mode.
- **Antigravity** (the Gemini CLI's successor — the preset is still `gemini` so existing nodes keep working; the app resolves it to the `agy` binary on modern installs) — resume, subagents, usage, permission mode.
- **Grok** — resume, subagents, recurring, branch, usage, permission mode.
- **OpenClaude** — a Claude-Code-compatible TUI for any OpenAI-compatible endpoint. Point it at your **local models** (Ollama, llama.cpp, LM Studio, …) or any provider. No badge support yet.
- **Custom agent** — a template you configure. It is not enabled by default.

<Callout type="info" title="Status badges are honest">
  Live status badges (RUNNING / NEEDS YOU) are driven by each agent's own hook
  system. Claude Code and Codex CLI drive badges today; the other presets
  launch and run normally — they just don't claim badge support they can't
  deliver.
</Callout>

<Callout type="info" title="You need the CLI installed">
  termsprawl launches the agent binary from your PATH (GUI launches also check
  `~/.local/bin` and `~/bin`; Antigravity resolves to `agy`). Install `claude`,
  `codex`, `agy`, `grok`, or `openclaude` yourself first; the agent node just
  runs it in your project. When the binary is missing, the node shows a notice
  naming it instead of closing silently.
</Callout>

## Spawn an agent

1. Right-click on the canvas.
2. Click **Claude Code**, **Codex CLI**, **Antigravity**, **Grok**, or
   **OpenClaude** directly in the **Open agent** section. The small marks help
   you recognize each agent; no submenu is needed.

A terminal node opens and starts the selected agent automatically. For example,
choosing **Codex** starts Codex CLI; choosing **Grok** starts Grok. You do not
need to type the agent command yourself. Reopening an existing live session
reattaches to that agent without starting a second copy.

For SSH projects, install the selected agent CLI on the remote host.

## Status badges

Agents that support hooks drive their status from the CLI. The node badge
shows the agent's state — **RUNNING** while it works, **NEEDS YOU** when it
stops for input. Badges come from the agent's own hook system, so they're
accurate.

## Resume and branch (Claude)

Claude Code nodes support conversation continuity:

- **Resume session in new node** — create a new node that reattaches to an
  existing conversation.
- **Branch session** — send the /branch command to fork the conversation.

## Context links

You can link agent nodes together so they can read each other's transcripts on
demand. Right-click an agent node, choose **link to another agent ▸**, and pick
a peer. This lets agents share context without you copying text between them.

## Connect agents with node links and A2A

Two newer connection types build on the same canvas:

- **Node links** — drag between an agent terminal and another node to route
  its output: write it to a file, inject it into a chat or terminal, or send
  it to a peer. See [Node links](/docs/node-links).
- **A2A send to peer** — right-click an agent node and pick **A2A send to
  peer ▸** to forward its output to an agent on another machine. See
  [Agent-to-agent](/docs/a2a).

## Managed accounts

Manage per-agent accounts in **Settings → Agent accounts**. This is where you set up a
Claude account, an API provider, or a peer endpoint — without pasting secrets
into a shell. Model providers live under **Settings → Model settings**, and
peer endpoints under **Settings → A2A peers**.

<Callout type="warn" title="Secrets stay in Settings">
  Configure provider keys and accounts in the Settings panel. Don't export them
  into a shell where they can leak into scrollback.
</Callout>

## Permission modes

Agents that support it expose a **permission mode** selector. Choose the mode
the CLI runs with — the available options depend on the CLI version you have
installed.

## Custom agents

The **Custom agent** preset is a template. To use it you enable and configure
it in Settings; until then it's visible but not spawnable. Point it at a
CLI binary that follows the same command pattern as the built-in presets.
